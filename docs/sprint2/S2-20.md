## 1. Resumen y Objetivo

Establecer la infraestructura de Integración Continua (CI) automatizada e independiente para `security-service` mediante GitHub Actions, junto con la publicación y documentación viva del contrato público de la API mediante la especificación OpenAPI 3 / Swagger UI.

Garantizar que:
1. La integración continua ejecute de forma automatizada `mvnw verify` con base de datos MySQL 8.4 de prueba y material criptográfico efímero, además de compilar la imagen Docker sin publicarla en cada Pull Request.
2. La documentación OpenAPI exponga todos los endpoints de autenticación, registro, perfil, administración y modelos de error sin revelar contraseñas reales, hashes criptográficos ni claves privadas.
3. Ninguna prueba unitaria ni de integración requiera la disponibilidad de microservicios remotos (`shipment-service` o `courier-service`), asegurando que la evidencia de CI quede identificada unívocamente por el commit de la entrega.

## 2. Criterios de Aceptación y Solución Implementada

### 2.1 Flujo de CI automatizado (`.github/workflows/ci.yml`)
Se diseñó un flujo de trabajo independiente en GitHub Actions estructurado en dos trabajos (*jobs*):

1. **Trabajo `verify` (Maven verify y pruebas aisladas):**
   - **Ambiente:** `ubuntu-latest` con JDK 25 (Eclipse Temurin) y caché de dependencias Maven.
   - **Servicio MySQL:** Contenedor de servicio `mysql:8.4` con comprobación de salud (*health-cmd* `mysqladmin ping`) en puerto 3306.
   - **Paso 1:** Ejecución de suite aislada con base de datos H2 en memoria y generación efímera de claves RSA (`./mvnw clean verify`).
   - **Paso 2:** Ejecución de migraciones Flyway y pruebas de persistencia contra la instancia real de MySQL (`TEST_DB_URL=jdbc:mysql://...`).
   - **Paso 3:** Verificación estricta de compilación y documentación Javadoc completa sin errores (`./mvnw javadoc:javadoc`).

2. **Trabajo `docker-build` (Construcción de imagen sin publicar):**
   - Depende del éxito del trabajo `verify`.
   - Ejecuta la construcción multietapa de la imagen Docker:
     ```bash
     docker build -t logitrack/security-service:ci-${{ github.sha }} .
     ```
   - Inspecciona la imagen para certificar la ejecución bajo el usuario no privilegiado `spring:spring`, la exposición del puerto `8083` y la ausencia total de secretos en las capas del contenedor.
   - No publica ni envía la imagen a registros públicos en Pull Requests, preservando la política de despliegue controlado.

### 2.2 Contrato público OpenAPI 3 y Swagger UI
Se incorporó la biblioteca estándar `springdoc-openapi-starter-webmvc-ui` (versión `2.8.17`) y se configuró la clase `OpenApiConfiguration`:
- **Ruta OpenAPI JSON:** `/v3/api-docs` (público sin autenticación).
- **Ruta Swagger UI:** `/swagger-ui/index.html` (público sin autenticación).
- **Esquema de seguridad:** Bearer JWT con formato `JWT` y algoritmo `RS256` bajo el identificador `bearerAuth`.
- **Rutas documentadas:**
  - `POST /api/v1/auth/register`: Registro público exclusivo para rol `CLIENTE`.
  - `POST /api/v1/auth/login`: Autenticación de credenciales y emisión de token portador Bearer.
  - `GET /api/v1/auth/me`: Consulta de perfil propio autenticado (requiere `bearerAuth`).
  - `GET /api/v1/auth/jwks`: Exposición pública del conjunto JWKS (RFC 7517) para verificación descentralizada.
  - `GET /api/v1/auth/public-key`: Exposición pública de la clave pública RSA en formato PEM.
  - `GET /api/v1/users/{id}`: Consulta administrativa de usuarios por UUID (requiere rol `ADMIN`).
  - `POST /api/v1/users`: Alta administrativa con asignación de roles privilegiados (requiere rol `ADMIN`).
  - `PUT/PATCH /api/v1/users/{id}/roles`: Actualización de roles de usuario (requiere rol `ADMIN`).
  - `PUT/PATCH /api/v1/users/{id}/customer-link`: Asociación confiable de `customerId` (requiere rol `ADMIN`).
  - `PUT/PATCH /api/v1/users/{id}/courier-link`: Asociación confiable de `courierId` (requiere rol `ADMIN`).
- **Garantía de confidencialidad:**
  - Los esquemas `UserResponse` y `ErrorResponse` omiten completamente campos de contraseñas o hashes.
  - Los ejemplos de `RegisterRequest` y `LoginRequest` utilizan contraseñas ilustrativas genéricas sin exponer valores de producción.
  - Las claves privadas RSA residen exclusivamente fuera del código y no forman parte de ningún esquema.

### 2.3 Aislamiento total sin dependencias de otros microservicios
- Toda la suite de pruebas unitarias, de integración y de contrato se ejecuta con dobles de prueba y fixtures locales (`src/test/resources/contracts/v1/identities.json`).
- Ninguna prueba realiza llamadas HTTP hacia `shipment-service` ni `courier-service`.
- La clave pública y el emisor se configuran dinámicamente mediante `RsaKeyProvider` en memoria para las pruebas locales.

## 3. Especificación del Flujo de Integración Continua

### 3.1 `.github/workflows/ci.yml`
```yaml
name: CI security-service (Java 25 y MySQL)

on:
  workflow_dispatch:
  pull_request:
  push:
    branches: [main, develop]

permissions:
  contents: read

concurrency:
  group: ci-security-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: Maven verify y pruebas aisladas
    runs-on: ubuntu-latest
    timeout-minutes: 15
    services:
      mysql:
        image: mysql:8.4
        env:
          MYSQL_DATABASE: security_test
          MYSQL_USER: security_test
          MYSQL_PASSWORD: test-only
          MYSQL_ROOT_PASSWORD: test-root-only
        ports: ['3306:3306']
        options: >-
          --health-cmd="mysqladmin ping -h 127.0.0.1"
          --health-interval=5s
          --health-timeout=5s
          --health-retries=30
    steps:
      - name: Obtener código fuente
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v4
        with:
          persist-credentials: false

      - name: Configurar Temurin 25 y caché Maven
        uses: actions/setup-java@b843ebf9b913146b38da2eaa7aeddf76074ae1ad # v4
        with:
          distribution: temurin
          java-version: '25'
          cache: maven

      - name: Suite aislada con H2 y material criptográfico efímero
        run: ./mvnw --batch-mode --no-transfer-progress clean verify

      - name: Migraciones Flyway y persistencia contra MySQL de integración
        env:
          TEST_DB_URL: jdbc:mysql://127.0.0.1:3306/security_test?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC
          TEST_DB_USERNAME: security_test
          TEST_DB_PASSWORD: test-only
        run: ./mvnw --batch-mode --no-transfer-progress test

      - name: Verificación estricta de compilación y Javadoc
        run: ./mvnw --batch-mode --no-transfer-progress javadoc:javadoc

  docker-build:
    name: Construcción de imagen de contenedor (sin publicar)
    needs: verify
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - name: Obtener código fuente
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v4
        with:
          persist-credentials: false

      - name: Construir imagen Docker multietapa Java 25
        run: docker build -t logitrack/security-service:ci-${{ github.sha }} .

      - name: Inspección de metadatos (usuario no privilegiado y puertos)
        run: |
          docker image inspect logitrack/security-service:ci-${{ github.sha }} --format 'User: {{.Config.User}}, Ports: {{json .Config.ExposedPorts}}'
          docker history logitrack/security-service:ci-${{ github.sha }}
```

## 4. Evidencia de Pruebas y Resultados de Ejecución

### 4.1 Suite `OpenApiDocumentationTest`
Se implementó y ejecutó la suite de verificación automatizada del contrato OpenAPI:
- `openApiSpecificationIsGeneratedAndSecure`: Valida la presencia de todos los endpoints, esquemas de datos y esquemas de seguridad Bearer JWT, así como la ausencia de cadenas sensibles (`PRIVATE KEY`, `$2a$`, `password_hash`).
- `swaggerUiIsPubliclyAccessible`: Valida que `/swagger-ui/index.html` responda HTTP 200 sin necesidad de autenticación.
