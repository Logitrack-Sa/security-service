# S2-16: Integrar security-service con Config Server sin externalizar secretos

## 1. Resumen y Objetivo

Integrar `security-service` con Spring Cloud Config Server mediante el mecanismo estándar `spring.config.import`, permitiendo externalizar y centralizar la configuración no sensible por perfiles (`dev` y `prod`) sin acoplamiento rígido ni esperas innecesarias de servicios remotos durante el ciclo de desarrollo y pruebas.

Asegurar de manera estricta que **ningún secreto criptográfico ni credencial de acceso resida jamás en los repositorios de configuración de Git**:
- La contraseña de base de datos (`DB_PASSWORD`),
- La clave privada RSA (`JWT_PRIVATE_KEY_LOCATION`),
- Y la contraseña de provisión del administrador inicial (`SECURITY_ADMIN_PASSWORD`),
deben suministrarse exclusivamente a través de variables de entorno seguras o volúmenes de secretos montados en tiempo de ejecución.

Incorporar validaciones de arranque preventivo (*fail-fast*) que aborten inmediatamente el inicio del contenedor si faltan secretos requeridos en entornos productivos.

---

## 2. Criterios de Aceptación y Solución Implementada

### 2.1 Centralización de configuración no sensible mediante `spring.config.import`

- **Dependencia:** Incorporación de `org.springframework.cloud:spring-cloud-starter-config` en `pom.xml`.
- **Compatibilidad:** Spring Cloud BOM 2025.0.3 para Boot 3.5.x, sin deshabilitar el verificador de compatibilidad.
- **Importación obligatoria en dev/prod:** 
  ```properties
  spring.config.import=configserver:${CONFIG_SERVER_URL:http://localhost:8888}
  ```
  La importación vive en application-dev/prod.properties y exige Config Server. El perfil test usa configuración aislada sin importación remota; las pruebas de bootstrap dev/prod usan un servidor simulado.
- **Propiedades centralizadas:**
  - `server.port`: Puerto del servicio (8083).
  - `spring.datasource.url` y `spring.datasource.username`: Conexión JDBC MySQL centralizada sin credenciales secretas.
  - `logging.level.com.logitrack`: Nivel de detalle de bitácora (`DEBUG` en dev, `INFO` en prod).
  - `logitrack.security.jwt.issuer`: Emisor URI confiable (`https://security-service`).
  - `logitrack.security.jwt.audiences`: Lista de destinatarios autorizados (`security-service,courier-service,shipment-service`).
  - `logitrack.security.jwt.ttl-seconds` / `expiration-ms`: Vigencia del token compatible tanto con segundos como con milisegundos centralizados.

---

### 2.2 Aislamiento y confidencialidad estricta de secretos

- **Cero secretos en Git:**
  Los repositorios de Git y las respuestas de Config Server solo contienen referencias a variables de entorno (`${DB_PASSWORD}`, `${JWT_PRIVATE_KEY_LOCATION}`) o valores no sensibles.
- **Inyección por entorno/montaje:**
  - `spring.datasource.password=${DB_PASSWORD:}`
  - `logitrack.security.jwt.private-key-location=${JWT_PRIVATE_KEY_LOCATION:}`
  - `security.admin.password=${SECURITY_ADMIN_PASSWORD:}`
- **Imposibilidad de filtraciones:** En ningún caso se comitean credenciales reales en `application.properties` ni en `config-repo`.

---

### 2.3 Validación preventiva (*fail-fast*) ante ausencia de secretos en producción

Se implementó el componente `SecretValidationConfiguration` (`ApplicationRunner`), el cual valida de forma estricta al iniciar en perfil `prod`:
1. **Contraseña de base de datos:** Si `spring.datasource.password` está vacío o no fue suministrado mediante `DB_PASSWORD`, aborta con:
   > *"Fallo de arranque: La contraseña de base de datos (DB_PASSWORD) es un secreto obligatorio y no fue suministrada."*
2. **Clave privada RSA:** Si `JWT_PRIVATE_KEY_LOCATION` no está configurada o el archivo especificado no existe o no tiene permisos de lectura, aborta con:
   > *"Fallo de arranque: La ubicación de la clave privada JWT (JWT_PRIVATE_KEY_LOCATION) es obligatoria en producción."*
3. **Contraseña segura de ADMIN:** Si `security.admin.enabled` es `true` y se detecta la valor inseguro `admin123` o una cadena en blanco, aborta con:
   > *"Fallo de arranque: Se requiere definir una contraseña segura para SECURITY_ADMIN_PASSWORD distinta al valor por defecto."*
