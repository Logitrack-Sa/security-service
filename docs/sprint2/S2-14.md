## 1. Resumen y Objetivo

Implementar el endpoint de consulta de identidad propia (`GET /api/v1/auth/me`) que expone el perfil del sujeto autenticado a partir de un token JWT firmado y validado criptográficamente por Spring Security (OAuth2 Resource Server).

Garantizar la protección perimetral e interna de las operaciones administrativas (`/api/v1/users/**`) reservándolas de forma exclusiva a usuarios con rol `ADMIN`, aplicando el principio de mínimo privilegio y prohibiendo taxativamente cualquier auto-modificación arbitraria de roles propios.

Asegurar respuestas de error HTTP estandarizadas y coherentes con el contrato:
- **`401 Unauthorized`** ante la ausencia, expiración o manipulación de tokens JWT, o ante cuentas deshabilitadas.
- **`403 Forbidden`** ante intentos de acceso a recursos privilegiados por usuarios autenticados sin el rol requerido (`CLIENTE`, `REPARTIDOR`).
- **`400 Bad Request`** con código `PRIVILEGE_ESCALATION` ante intentos de auto-modificación de roles.

## 2. Criterios de Aceptación y Solución Implementada

### 2.1 Perfil autenticado sin datos sensibles (`GET /api/v1/auth/me`)

- **Endpoint:** `GET /api/v1/auth/me` (protegido por Resource Server).
- **Extracción de identidad:** La identidad se extrae directamente del claim `sub` del `Jwt` autenticado (`UUID` del usuario), inyectado mediante `@AuthenticationPrincipal Jwt jwt`.
- **Información expuesta:** Devuelve el DTO inmutable `UserResponse`:
  ```json
  {
    "id": "e4f8a29b-8c10-4d89-b873-456789abcdef",
    "email": "cliente.me@logitrack.com",
    "username": "cliente_me",
    "name": "Cliente Perfil",
    "roles": ["CLIENTE"],
    "enabled": true,
    "customerId": "11111111-2222-3333-4444-555555555555",
    "courierId": null
  }
  ```
- **Confidencialidad absoluta:** Ni la contraseña en texto plano, ni el hash BCrypt, ni material criptográfico son incluidos en la respuesta.
- **Sin JWT válido responde 401:** Las peticiones sin cabecera `Authorization: Bearer <token>`, con tokens vencidos o con firmas criptográficas alteradas son interceptadas por `AuthenticationEntryPoint` y responden **`401 Unauthorized`** con payload uniforme:
  ```json
  {
    "timestamp": "2026-10-26T11:00:00Z",
    "status": 401,
    "error": "Unauthorized",
    "code": "UNAUTHORIZED",
    "message": "Token JWT ausente, expirado o con firma inválida",
    "path": "/api/v1/auth/me"
  }
  ```
- **Cuentas deshabilitadas:** Si un usuario se encuentra marcado con `enabled = false`, la invocación a `GET /api/v1/auth/me` es rechazada con **`401 Unauthorized`**.

---

### 2.2 Rutas de administración y roles exclusivas para ADMIN

- **Protección de rutas `/api/v1/users/**`:**
  - `POST /api/v1/users`: Alta privilegiada de usuarios (roles `ADMIN`, `REPARTIDOR`, vínculos `customerId`/`courierId`).
  - `GET /api/v1/users/{id}`: Consulta administrativa de usuarios.
  - `PUT /api/v1/users/{id}/roles`: Modificación de roles.
  - `PUT /api/v1/users/{id}/customer-link`: Asociación confiable de `customerId`.
  - `PUT /api/v1/users/{id}/courier-link`: Asociación confiable de `courierId`.
- **Autorización en el backend:**
  - Configurado en `SecurityConfiguration` mediante `.requestMatchers("/api/v1/users", "/api/v1/users/**").hasRole("ADMIN")`.
  - `JwtAuthenticationConverter` transforma la lista del claim `roles` del JWT en autoridades Spring Security con prefijo `ROLE_` (`ROLE_ADMIN`, `ROLE_CLIENTE`, `ROLE_REPARTIDOR`).
  - Usuarios con rol `CLIENTE` o `REPARTIDOR` reciben inmediatamente **`403 Forbidden`** emitido por `AccessDeniedHandler`:
    ```json
    {
      "timestamp": "2026-10-26T11:00:00Z",
      "status": 403,
      "error": "Forbidden",
      "code": "FORBIDDEN",
      "message": "Acceso denegado: permisos insuficientes para la operación solicitada",
      "path": "/api/v1/users"
    }
    ```

---

### 2.3 Prohibición de auto-modificación arbitraria de roles

- En `UserService.updateRoles(UUID userId, Set<Role> roles)`, se comprueba el sujeto autenticado en el `SecurityContext`:
  - Si el usuario autenticado coincide con el identificador del usuario cuyos roles se pretenden alterar (intento de auto-escalación o auto-modificación de roles propios), la operación es abortada con `PrivilegeEscalationException`:
    ```json
    {
      "status": 400,
      "error": "Bad Request",
      "code": "PRIVILEGE_ESCALATION",
      "message": "No está permitida la auto-modificación arbitraria de roles propios",
      "path": "/api/v1/users/..."
    }
    ```
  - Un administrador solo puede modificar los roles de *otros* usuarios del sistema, previniendo alteraciones accidentales o maliciosas sobre su propia cuenta privilegiada.
