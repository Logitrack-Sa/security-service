## 1. Resumen y Objetivo

Construir la infraestructura de contenerización para `security-service` mediante un `Dockerfile` multietapa y un archivo `.dockerignore` riguroso, utilizando Java 25 (Eclipse Temurin) tanto en la fase de compilación como en el runtime final.

El objetivo central de seguridad operacional es garantizar que **ningún secreto, certificado, clave criptográfica ni credencial de acceso resida dentro de las capas de la imagen Docker**. La inyección de material criptográfico (par de claves RSA) y contraseñas (base de datos MySQL) se realiza exclusivamente en tiempo de ejecución a través de variables de entorno seguras o volúmenes montados en el sistema de archivos del contenedor (`/secrets`).

Además, el contenedor debe ejecutarse bajo un usuario de sistema sin privilegios (`spring:spring`), exponiendo un puerto configurable (por defecto `8083`).

---

## 2. Criterios de Aceptación y Solución Implementada

### 2.1 Construcción multietapa con Java 25 y runtime mínimo

Se diseñó un `Dockerfile` en dos etapas:
1. **Etapa 1 (`builder`):** Utiliza la imagen base oficial `maven:3-eclipse-temurin-25`. Copia exclusivamente el descriptor `pom.xml` y el árbol `src/`, ejecutando `mvn clean package -DskipTests -B` para generar el archivo ejecutable `security-service-*.jar`.
2. **Etapa 2 (`runtime`):** Utiliza la imagen base mínima `eclipse-temurin:25-jre` (sin herramientas de compilación, compiladores ni código fuente intermediario).

### 2.2 Usuario sin privilegios y directorios de montaje dedicados

Por principios de mínimo privilegio y defensa en profundidad:
- Se crea el grupo y usuario de sistema `spring:spring` con shell nula (`/sbin/nologin`).
- Se crean los directorios `/secrets` y `/config` con propiedad asignada a `spring:spring`.
- Se copia el artefacto compilado como `/app/app.jar` con permisos restringidos.
- Se define la directiva `USER spring:spring` antes del punto de entrada, asegurando que ningún proceso se ejecute como `root`.

### 2.3 Parametrización y configuración de ejecución

- **Variables de entorno por defecto:**
  - `SERVER_PORT=8083`
  - `SPRING_PROFILES_ACTIVE=prod`
  - `JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0 -Djava.security.egd=file:/dev/./urandom"`
- **Puerto expuesto:** `EXPOSE 8083`.
- **Punto de entrada (`ENTRYPOINT`):** `["sh", "-c", "exec java $JAVA_OPTS -jar app.jar"]` para permitir la propagación de señales de terminación (`SIGTERM`) y la configuración dinámica de memoria mediante flags del contenedor.

### 2.4 Exclusión estricta de secretos vía `.dockerignore`

El archivo `.dockerignore` previene la inclusión inadvertida de cualquier archivo sensible o innecesario durante el contexto de construcción:
- Exclusión de directorios `.git/`, `target/`, `.idea/`, `logs/`, `docs/`.
- Exclusión de patrones de claves y certificados: `*.pem`, `*.key`, `*.pub`, `*.pk8`, `*.pfx`, `*.keystore`, `*.jks`.
- Exclusión de variables locales: `*.env*`.

## 3. Estructura de los Archivos Creados

### 3.1 `Dockerfile`
```dockerfile
# --- Etapa 1: Build multietapa con Java 25 ---
FROM maven:3-eclipse-temurin-25 AS builder
WORKDIR /app

# Copiar descriptores del proyecto y código fuente
COPY pom.xml ./
COPY src/ src/

# Compilar y empaquetar artefacto ejecutable omitiendo pruebas en el empaquetado de imagen
RUN mvn clean package -DskipTests -B

# --- Etapa 2: Runtime mínimo con Java 25 y usuario sin privilegios ---
FROM eclipse-temurin:25-jre AS runtime
WORKDIR /app

LABEL org.opencontainers.image.title="security-service" \
      org.opencontainers.image.description="Servicio de autenticación, gestión de identidades y emisión de JWT para LogiTrack" \
      org.opencontainers.image.vendor="Logitrack-Sa"

# Crear usuario y grupo de sistema sin privilegios
RUN groupadd -r spring && useradd -r -g spring -s /sbin/nologin spring

# Directorios dedicados a montaje de secretos y configuraciones externas
RUN mkdir -p /secrets /config && chown -R spring:spring /app /secrets /config

# Copiar exclusivamente el artefacto final desde el constructor
COPY --from=builder --chown=spring:spring /app/target/security-service-*.jar app.jar

# Variables de entorno y puerto parametrizable (por defecto 8083)
ENV SERVER_PORT=8083 \
    SPRING_PROFILES_ACTIVE=prod \
    JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0 -Djava.security.egd=file:/dev/./urandom"

USER spring:spring

EXPOSE 8083

ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar app.jar"]
```
