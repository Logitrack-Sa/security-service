## 1. Resumen y Objetivo

Implementar el endpoint de inicio de sesión (`POST /api/v1/auth/login`) que valida credenciales de usuario y emite tokens JWT firmados digitalmente mediante el algoritmo criptográfico asimétrico **RS256**, estrictamente alineado con el contrato de arquitectura del Sprint 2.

Garantizar que la **clave privada RSA permanezca exclusivamente dentro de `security-service`** provista por mecanismos seguros de entorno o secretos montados, exponiendo a los microservicios consumidores únicamente la clave pública y el identificador de clave (`kid`) a través de un endpoint JWKS (RFC 7517) y un endpoint de clave pública en formato PEM.

Prevenir ataques de enumeración de usuarios respondiendo con un error HTTP `401 Unauthorized` genérico e idéntico ante credenciales incorrectas, usuarios inexistentes o cuentas deshabilitadas, asegurando que nunca se registren en logs ni contraseñas en texto plano ni tokens emitidos.

## 2. Criterios de Aceptación y Solución Implementada

### 2.1 Claims estándar y de dominio confiables con duración configurable

- **Endpoint de inicio de sesión:** `POST /api/v1/auth/login` (público, accesible sin autenticación previa).
- **Parámetros aceptados:** Acepta indistintamente nombre de usuario (`username`) o dirección de correo electrónico (`email`), junto con la contraseña obligatoria (`password`).
- **Respuesta exitosa:** HTTP `200 OK` con payload inmutable `LoginResponse`:
  ```json
  {
    "accessToken": "eyJhbGciOiJSUzI1NiIsImtpZCI6ImxvZ2l0cmFjay1tYWluIiwidHlwIjoiSldUIn0...",
    "tokenType": "Bearer",
    "expiresIn": 3600
  }
  ```
- **Estructura estricta del JWT emitido:**
  - **Header JOSE:**
    - `alg`: `RS256` (RSA Signature with SHA-256).
    - `typ`: `JWT`.
    - `kid`: Identificador de versión de clave para rotación (por defecto `logitrack-main`, configurable vía `JWT_KEY_ID`).
  - **Claims de Carga Útil (Payload):**
    - `sub`: Identificador único de usuario persistido (`UUID` como cadena).
    - `roles`: Lista de roles asignados en base de datos (`["ADMIN"]`, `["CLIENTE"]`, `["REPARTIDOR"]`).
    - `iss`: Emisor URI confiable (por defecto `https://security-service`, configurable vía `JWT_ISSUER`).
    - `aud`: Audiencia con los servicios autorizados (por defecto `["courier-service", "shipment-service"]`, configurable vía `JWT_AUDIENCES`).
    - `iat`: Timestamp UTC de emisión (NumericDate).
    - `exp`: Timestamp UTC de expiración según la duración configurable (por defecto 3600 segundos, configurable vía `JWT_TTL_SECONDS`).
    - `customerId`: UUID del cliente asociado en base de datos (presente solo si el usuario tiene vínculo confiable persistido).
    - `courierId`: UUID del repartidor asociado en base de datos (presente solo si el usuario tiene vínculo confiable persistido).
- **Inmutabilidad y confianza de vínculos:** Los identificadores `customerId` y `courierId` se extraen exclusivamente del registro del usuario persistido y gestionado por administradores; nunca son aceptados ni alterados desde parámetros de login.

### 2.2 Material criptográfico y aislamiento de la clave privada

- **Aislamiento de la clave privada:** La clave privada RSA reside y se procesa únicamente en `security-service`. Nunca es serializada ni transmitida fuera del proceso.
- **Carga desde secreto/montaje:**
  - `RsaKeyProvider` inspecciona la ruta configurada en `JWT_PRIVATE_KEY_LOCATION` (o `logitrack.security.jwt.private-key-location`).
  - Soporta claves privadas en formato PEM PKCS#8.
  - Si se proporciona `JWT_PUBLIC_KEY_LOCATION`, carga la clave pública; si no se especifica, deduce la clave pública directamente del módulo y exponente del par RSA (`RSAPrivateCrtKey`).
- **Generación efímera para pruebas y desarrollo local:** Si no se especifica ruta a clave privada o el archivo no existe, `RsaKeyProvider` inicializa de forma transparente un par de claves RSA de 2048 bits en memoria, permitiendo ejecutar builds, pruebas automatizadas y desarrollo local sin requerir secretos externos.
- **Distribución de claves para consumidores:**
  - `GET /api/v1/auth/jwks`: Expone el conjunto de claves públicas en formato estándar RFC 7517 (JWKS) conteniendo `kty: "RSA"`, `use: "sig"`, `alg: "RS256"`, `kid`, `n` y `e`.
  - `GET /api/v1/auth/public-key`: Expone la clave pública codificada en estándar PEM (X.509) junto con metadatos de algoritmo y `kid`.

### 2.3 Manejo de autenticación inválida y confidencialidad estricta

- **Prevención de enumeración de usuarios:**
  - Si el usuario no existe en la base de datos,
  - Si la cuenta se encuentra deshabilitada (`enabled = false`),
  - O si la contraseña provista no coincide con el hash BCrypt,
  El sistema responde de manera uniforme con HTTP `401 Unauthorized` y payload de error estándar:
  ```json
  {
    "timestamp": "2026-10-26T10:35:00Z",
    "status": 401,
    "error": "Unauthorized",
    "code": "UNAUTHORIZED",
    "message": "Credenciales inválidas",
    "path": "/api/v1/auth/login"
  }
  ```
- **Confidencialidad de contraseñas y tokens:**
  - Ningún log registra contraseñas en texto plano, hashes criptográficos ni cadenas de tokens JWT.
  - Las excepciones de autenticación son capturadas por `GlobalExceptionHandler` y nunca exponen trazas de pila (stack traces).

## 3. Propiedades de Configuración

| Propiedad | Variable de Entorno | Valor por Defecto | Propósito |
|---|---|---|---|
| `logitrack.security.jwt.private-key-location` | `JWT_PRIVATE_KEY_LOCATION` | `""` (efímera en memoria) | Ruta al archivo PEM con la clave privada RSA |
| `logitrack.security.jwt.public-key-location` | `JWT_PUBLIC_KEY_LOCATION` | `""` (deducida de privada) | Ruta opcional al archivo PEM con la clave pública RSA |
| `logitrack.security.jwt.key-id` | `JWT_KEY_ID` | `logitrack-main` | Identificador de clave presente en la cabecera `kid` |
| `logitrack.security.jwt.issuer` | `JWT_ISSUER` | `https://security-service` | Emisor URI confiable en el claim `iss` |
| `logitrack.security.jwt.audiences` | `JWT_AUDIENCES` | `courier-service,shipment-service` | Audiencias autorizadas en el claim `aud` |
| `logitrack.security.jwt.ttl-seconds` | `JWT_TTL_SECONDS` | `3600` | Duración del token en segundos antes de expirar |
